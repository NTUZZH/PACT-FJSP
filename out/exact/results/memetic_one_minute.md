## Rules

- a record counts when the planner calls it valid (timed_campaign_plan.cell_states, timing_validity.classify_single_thread: validated, wall-clock budget, one thread on one core of the slots, cpu_share >= 0.9); a cell enters with all its runs valid

- request clock of p124: a run started from the rule schedule at run time t - o_rule, a run started from the policy's schedule at run time t - max(o_pol, o_rule) (p94.read_cells), the greedy schedule from o_pol on, the sampled schedules the policy record's best so far; read at 60 s
- best of the runs: per cell the shortest incumbent of the runs of one set at the same time (p124.best_of); each side of a comparison takes the seeds of its own set
- difference: 100 (first - second) / second per cell, negative = the first-named method is shorter; mean and 95% interval by p94.compare_at (instance-level cluster bootstrap over base instances, fresh default_rng(7) per quantity); direction from the unrounded interval
- verdicts of smp_vs_m60 and smp_vs_mp60 per combination: ahead: the instance-level 95% interval lies below zero and the Holm-adjusted one-sided bootstrap p for "the policy is shorter" (draws of that interval) is below alpha; behind: the interval lies above zero and the Holm-adjusted one-sided bootstrap p for "the policy is longer" (its own Holm family) is below alpha; not distinguishable otherwise. No seed-level test exists for one run. (here the first-named method is the policy's sampled schedules)
- decision table: the 60-s values take the places of the two memetic columns (rule only: the column started from the rule schedule alone); each 60-s value a mean over the cells of every other value of its row; lowest column by p94.lowest over the printed values of the six columns, a tie counting in each tied column
- p124's smp_vs_best at 60 s, the two memetic columns of its decision table at 60 s, the bold columns of its twelve rows and its count of rows whose lowest column uses the policy: recomputed here and equal to its record, or the script refuses
